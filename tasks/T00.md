# T00: Środowisko i punkt startu
## Czytaj
docs/03-architecture.md A1–A2; docs/06-context.md C1–C3. Nie czytaj wszystkich specyfikacji.

## Cel
Ustalić realne środowisko i rozpocząć pracę bez przebudowywania planu.

## Wykonanie
1. Sprawdź istniejący folder, git status i czy są cudze zmiany. Nowy projekt
twórz w osobnym katalogu; nie w istniejącym niepowiązanym repo.
2. Rozpoznaj system/architekturę i Node: na Macu sw_vers, uname -m,
node --version, npm --version, git --version. Nie czytaj env ani sekretów.
3. Gdy to chmura/Linux, oznacz brak testu iMaca i kontynuuj lokalny build tam.
4. Na docelowym Macu wybierz binarium Node 24 LTS x64 zgodne z systemem,
zweryfikuj patch i przypnij .nvmrc. Bez sudo, zmiany macOS i wielkich instalacji.
Jeśli nie wolno instalować, przygotuj dokładną instrukcję tej jednej zależności.
5. Zrób smoke test node:sqlite w tmpdir: polskie znaki, nowe linie, transakcja,
restart połączenia, backup i odczyt kopii. Nie dotykaj danych użytkownika.
6. Zachowaj krótki wynik zgodności i ewentualny konkretny blocker.
Uruchom dostarczony check-context. Ustal nazwę folderu i brak remote,
jeśli GitHub nie jest jeszcze dostępny.

## Odbiór
- Jest konkretna wersja Node lub jawny blocker i ścieżka dalszej pracy.
- Test SQLite ma rzeczywisty wynik dla obecnego środowiska.
- Nie stwierdzono zgodności z Maciem na podstawie testu Linux.
- Rdzeń pamięci i aktywna karta działają; brak importu prywatnych plików.

## Poza tym zadaniem
Nie twórz jeszcze ekranów wszystkich ćwiczeń, nie instaluj LLM i nie publikuj repo.

## Zamknięcie
Uaktualnij STATE.md i status w tasks/INDEX.md. Zapisz rzeczywiste komendy
i wyniki. Uruchom node scripts/check-context.mjs. Sprawdź diff przed commitem.
Jeśli kryterium wymaga niedostępnego iMaca, zapisz VERIFY_ON_MAC, nie fikcyjny sukces.
