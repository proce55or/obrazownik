# T09: iMac i prywatne wersjonowanie
## Czytaj
docs/03-architecture.md A2 i A4; docs/07-git-privacy.md G1–G4; docs/05-acceptance.md Q4.

## Cel
Przekazać program do rzeczywistego uruchamiania i zabezpieczyć granicę repo/dane.

## Wykonanie
1. README z krótkim uruchomieniem, folderem danych i przywracaniem kopii.
Start-Obrazownik.command bez sudo, podwójnej instalacji i zabijania obcych procesów.
2. Repo-check śledzonych/staged plików oraz check-context w npm run check.
Test repo-check na syntetycznych nazwach bazy, sekretu i modelu.
3. Zweryfikuj .gitignore i brak prawdziwych danych w historii nowych commitów.
4. Jeśli dostęp do GitHub autoryzowany i tożsamość jednoznaczna, prywatny remote,
kontrola private=true, push tylko kodu. Brak dostępu zapisz, nie blokuj lokalnego MVP.
5. CI opcjonalne dla małych check na syntetycznych danych; sprawdź limity konta.
Nigdy nie przekazuj produkcyjnego katalogu danych do workflow.
6. Na iMacu wykonaj Q4. Jeśli brak dostępu, daj dokładną krótką instrukcję
użytkownikowi i oznacz VERIFY_ON_MAC. Nie twierdź, że program już działa na Macu.

## Odbiór
- Dostępna instrukcja startu i odtwarzania oraz faktyczny wynik środowiska.
- Repo po skonfigurowaniu jest zweryfikowane jako prywatne.
- Pliki danych i modele nie wchodzą do commitów.
- Lokalny MVP można używać bez synchronizacji z GitHubem.
- Licencje są jawnie zaplanowane; brak fikcyjnego właściciela praw.

## Poza tym zadaniem
Bez publicznego repo, Pages, publikacji paczki, płatnej infrastruktury i dostępu z Internetu.

## Zamknięcie
Uaktualnij STATE.md i status w tasks/INDEX.md. Zapisz rzeczywiste komendy
i wyniki. Uruchom node scripts/check-context.mjs. Sprawdź diff przed commitem.
Jeśli kryterium wymaga niedostępnego iMaca, zapisz VERIFY_ON_MAC, nie fikcyjny sukces.
