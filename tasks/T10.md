# T10: Pilotaż użyteczności
## Czytaj
docs/05-acceptance.md Q5; docs/08-later.md L1–L2.

## Cel
Sprawdzić, czy program pomaga autorowi, zanim powstaną kolejne integracje.

## Wykonanie
1. Przygotuj krótką instrukcję dobrowolnych sesji i niezależnych próbek.
2. Potwierdź, że użytkownik umie rozpocząć, pominąć i przerwać ćwiczenie.
3. Zbieraj faktyczne opinie i samooceny lokalnie, nie w publicznych issues.
4. Po dostępnych obserwacjach ustal: zbyt trudne polecenia, monotonia,
nieprzydatne podpowiedzi, problem startu pisania lub zmęczenie.
5. Wybierz najwyżej 3 usprawnienia z konkretnym przykładem zachowania.
6. LLM lub telefon rozważ dopiero jako osobny zakres, jeśli rozwiązuje problem.

## Odbiór
- Przygotowanie pilotażu oznaczone osobno od jego przeprowadzenia.
- Wyniki opisują obserwacje użytkownika, nie domniemaną zmianę mózgu.
- Nowe pomysły mają uzasadnienie i priorytet.
- Jeśli brak jeszcze obserwacji, status oczekiwania jest jawny; aplikacja działa.

## Poza tym zadaniem
Nie wymyślaj wyniku wielotygodniowego pilotażu w jednej sesji i nie dodawaj LoRA.

## Zamknięcie
Uaktualnij STATE.md i status w tasks/INDEX.md. Zapisz rzeczywiste komendy
i wyniki. Uruchom node scripts/check-context.mjs. Sprawdź diff przed commitem.
Jeśli kryterium wymaga niedostępnego iMaca, zapisz VERIFY_ON_MAC, nie fikcyjny sukces.
